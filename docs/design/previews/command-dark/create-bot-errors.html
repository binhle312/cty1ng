E1 · Field errors on a stepApprovedErrors show under the field, in red, with the fix in the words. When they show: a size error at once while you type (the counter turns red); a taken name when you leave the field (checked against the bot list the page already has, upper and lower case are the same); an empty required field only after you click Next. Next stays on: a click with errors keeps you on the step and moves focus to the first error. The preview shows what you typed. Limits: name 1-32, description 1-160, persona 1-8,000 characters, history 10-80 %. The numbers are settings with these defaults (no hardcoding).

E3 · Create finds problemsApprovedThe server checks everything again on Create. Things can change while you fill in the steps, for example a bot with the same name made in another tab, or a key removed in Settings. Then nothing is created. The steps with a problem turn red with "!" in the stepper, and their sections in the preview card get a red (!) icon, with no text. A click on the step or the section opens that step, where the message shows under the field (as in E1). Create is off (40 %) until they are fixed. Your input is kept.

E4 · SendingApprovedWhile the request is on its way, Create is off (40 %) and shows a spinner with the label "Creating". Back is off too, and the form is read-only, so nothing changes under the request. The preview card has no amber section and no Edit links, and its pill says Creating. A double click sends one request only. When the server answers: the bot page opens (success), E3 (problems) or E5 (failed).

Step 4 of 4.BackTry again
E5 · Create failedApprovedFor an error that is not about your input (no connection, server error), a red banner shows under the stepper. No stack trace and no internal text (AGENTS.md rule). Your input stays. The preview card shows every section as done, with Edit, and the pill goes back to Not created yet. Try again sends the same request. Create is safe to send twice: the request has a key, so a retry never makes two bots.
