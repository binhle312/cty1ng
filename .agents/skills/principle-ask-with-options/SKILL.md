# Ask with options

A question moves work to the person who answers. Give that person what they need to decide on the first read. This applies to each question in a chat, a plan, a PR or a question dialog.

1. Look for the answer first. Read the code, the docs and the records, and run a probe. Ask only about a choice that the person owns.
2. Say the decision in one sentence. Define each term that the person may not know.
3. Give a real example with real values: what the person would see in the app or the repo, in the order that it occurs.
4. List each real option, and say what it changes. Include "change nothing" when that is a real option. A yes-or-no question lists what each answer causes.
5. Give the tradeoff of each option: the benefit and the cost.
6. Give the risk of each option: what can go wrong, how the person would notice it, and how to undo it.
7. Recommend one option, put it first, and give the reason.
8. Say how you know each fact: you ran it, you read it, or you do not know. Do not give a cost or a likelihood that you did not measure as a fact.

Ask about one decision in each question. Make each question complete, because the reader may see only that question. Use plain words, and keep it short: one line for each tradeoff and each risk is usually enough.

**Done:** Each question has an example, options, a tradeoff and a risk for each option, and a recommendation. The person can choose without another question about what the options mean.
