# Daytime rehearsal

Use a daytime rehearsal before the first night and after a change to the skill. Use disposable paths and fake GitHub data. Apply the [night rule](../SKILL.md#night-rule).

1. Record the harness, card, owner trigger, run ID and writable roots. Test a near-miss trigger as well as the exact go.
2. Trace chief analysis and read-only leader analysis. Establish the spec before dispatch. Check two independent leaders, dependency order, worktree ownership and PR ownership.
3. Trace the brief, chief assignment and plan check before code. Trace the chief starting the pair in the clean checkout. Check the pair, model tier, effort and helper roles. Plant a reviewer mismatch, unlisted helper, failed start and leader-supplied replacement. Verify the chief's response and grant record against the original sources.
4. Trace an ordinary permitted write, a safe rerun and the effects that stay for the owner. Check a held unknown effect, a recorded denial, stop during CI, the heartbeat wake and crash recovery.
5. Use the same sandbox profile and path layout as dispatch. Record a normal leader-journal write. Check that the Codex leader cannot write the chief's grant file, and that its bytes stay the same. Verify that both processes serialize on the read-only lock. Record what a Claude trace can show and where write enforcement is absent.
6. Record a granted merge with a fake GitHub tool. Capture the synced claim, Ready result, final PR read, exact arguments, and pinned result. Test a moved head, a second caller and time advancing during the claim. Trace the cap, P3 fixes and advice. Test the file scope and a second grant while main is red.
7. Check the morning page against the frozen report. Include an owner merge, an audit gap, a late result and a result that remains uncertain. Confirm that cleanup cancels only the recorded timer IDs.

Save the card, trace, reviewer reports, journals, command log and page. Name the actual tools and revision. A fake tool can check the exact payload and local behavior. Separate owner approval is required for the live disposable-PR exercise. Before real use, record that GitHub refuses a previously checked SHA after a head change and leaves the PR open at the new head.
